# Сетевой морской бой

Фронтенд: https://ivantimurov13-design.github.io/morskoy-boy/
API: https://mpxlab.ru/sea-battle-api/health

Один капитан выбирает режим и создаёт комнату, второй вводит шестизначный
код на своём устройстве. Капитан второго игрока определяется автоматически.
Оба расставляют корабли и нажимают «Флот готов». Все три режима доступны по
сети. После победы оба могут согласиться на реванш в той же комнате.

Нужен интернет. Закрытие страницы не удаляет партию: кнопка «Вернуться в
сетевой бой» восстанавливает её в том же браузере. Safari и приложение с
экрана «Домой» могут иметь раздельное хранилище: начинайте и продолжайте бой
одним способом. Комната истекает через 24 часа без игрового действия.
Очистка данных браузера или выход через «Другая комната» удаляет локальный
ключ доступа, одного кода недостаточно для восстановления занятого места.

## Устройство сервиса

- Один процесс Node.js, без дополнительных npm-зависимостей.
- Авторитетное состояние на сервере; используется общий `src/engine.js`.
- HTTPS-запросы с опросом раз в 2 секунды (7 секунд в фоне).
- Сопернику передаются только потопленные корабли, счёт и результаты ходов.
- Случайные ключи игроков передаются в Authorization, в файлах — только SHA-256.
- JSON-файлы заменяются атомарно с fsync. Ходы выполняются последовательно.
- Номер ревизии защищает ходы, requestId делает повторы идемпотентными.
- Подготовка разных флотов и голоса за реванш могут происходить одновременно.
- Ограничены размер запросов, частота, число комнат (100) и срок хранения.
- Сессии приватные, но код приглашения надо сообщать только своему сопернику.

## Размещение и откат

SSH-псевдоним: `wb-edge`. Сервис: `sea-battle.service`, пользователь: `sea-battle`.
Слушает только `127.0.0.1:4188`. Системные пакеты Node.js не устанавливаются:
официальный бинарный файл с проверкой SHA-256 находится в
`/opt/sea-battle/runtime/bin/node`. Версии кода — `/opt/sea-battle/releases/`,
активная версия — символьная ссылка `/opt/sea-battle/current`.
Данные — `/var/lib/sea-battle` (0700); они не входят в репозиторий или веб-сайт.
Память ограничена 160 МБ, CPU — 25% одного ядра, процесс непривилегированный.

Единственное дополнение к существующему HTTPS-сайту: include
`/etc/nginx/snippets/sea-battle-location.conf` в его server-блоке. Основной
location `/` и продление сертификата не меняются. Снимок конфигурации перед
первым подключением хранится в `/opt/sea-battle/backups/`.

Чтобы отключить только игру: убрать строку include из HTTPS-конфигурации,
выполнить `nginx -t` и только при успехе `systemctl reload nginx`, затем
`systemctl disable --now sea-battle`. Не восстанавливать старую конфигурацию
вслепую, если после установки на сервере были другие изменения.

Обновление backend: загрузить новый каталог выпуска, проверить тесты,
переключить `current`, перезапустить только `sea-battle`, проверить `/health`.
При неудаче вернуть ссылку на прошлый выпуск и перезапустить только игру.
Для фронтенда: `npm run deploy`; возврат — перепубликовать предыдущую версию.

## Разработка

```sh
DATA_DIR=/tmp/sea-dev ALLOWED_ORIGINS=http://127.0.0.1:4174 node multiplayer/server.mjs
VITE_MULTIPLAYER_URL=http://127.0.0.1:4188 npm run dev -- --host 127.0.0.1 --port 4174
npm test
```

Тесты проверяют секретность, авторизацию, конфликт ходов, ограничения,
радар, полную партию, реванш и восстановление после перезапуска процесса.
Для игры в браузере дополнительно проверяются две независимые сессии,
потеря сети и восстановление, мобильная ширина и прежняя игра с ботом.
